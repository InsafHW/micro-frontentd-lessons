Изоляция стилей и ошибок

Глобальное пишет только Shell. Каждый МФ изолирует свои стили и ловит свои ошибки. Shell — последняя линия.

Стили: три уровня

УровеньИнструментГарантияНе спасает от
СоглашениеПрефикс команды, BEM: .catalog-buyДисциплинаЗабытого префикса, селекторов по тегу
Сборка*.module.css, Vue <style scoped>, CSS-in-JSУникальные классы / data-v-…Глобальных селекторов по тегу у других команд
БраузерShadow DOMСелекторы не пересекают границуНаследуемых свойств и CSS-переменных: они проходят (это плюс для токенов)

Правила

  • Глобальный CSS (reset, токены --*) — только Shell. Команды берут цвета из токенов.
  • Никаких селекторов по тегу (button, h2) в коде команды.
  • CSS remote приходит <link> с его сервера и не выгружается при размонтировании.
  • Для Shadow DOM стили кладут внутрь shadow root: стили из <head> туда не попадут.

Ошибки: кто ловит

ГдеЛовит
Рендер React-дереваError boundary (в МФ и в Shell вокруг remote)
Обработчики событий, setTimeout, промисыBoundary — нет. Свой try/catch + window error / unhandledrejection
Vue-приложение из mount()app.config.errorHandler внутри МФ: рендер, обработчики, хуки, setup(), watchers, директивы, transitions
Слушатель чужого событияОтчёт как uncaught. До отправителя не доходит, остальные слушатели вызываются
Загрузка remote.catch() у import() / boundary вокруг lazy

// Shell: boundary сбрасывается при навигации
<RemoteBoundary name="Каталог" resetKey={path}>…</RemoteBoundary>
componentDidUpdate(prev) { if (this.state.error && prev.resetKey !== this.props.resetKey) this.setState({ error: null }) }

// Vue МФ: своя граница ошибок внутри mount()
app.config.errorHandler = (err, _i, info) => {
  console.error(info, err)
  queueMicrotask(() => { app.unmount(); el.innerHTML = '<div class="fallback">…</div>' })
}
