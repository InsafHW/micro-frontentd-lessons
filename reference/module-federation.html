Module Federation

Runtime-интеграция: remote публикует витрину, а хост по import() подгружает код по сети и делит с ним зависимости.

Термины

hostПотребляет чужие модули во время работы (remotes)
remoteОтдаёт модули наружу (exposes)
exposesПубличный контракт remote: имя → файл. Всё прочее — внутреннее
remoteEntry.js / mf-manifest.jsonВитрина remote: exposes, shared, publicPath. Имя стабильно между деплоями, поэтому его не кэшируют надолго
sharedЗависимости, которые загружаются один раз на всех

Конфиг (Vite, @module-federation/vite)

// remote
federation({ name: 'catalog', filename: 'remoteEntry.js', manifest: true,
  exposes: { './Catalog': './src/Catalog.tsx' },
  shared: { react: { singleton: true }, 'react-dom': { singleton: true } } })
// + base: 'https://cdn/catalog/'  — чтобы чанки грузились с сервера remote

// host
federation({ name: 'shell',
  remotes: { catalog: { type: 'module', name: 'catalog', entry: 'https://cdn/catalog/remoteEntry.js' } },
  shared: { react: { singleton: true }, 'react-dom': { singleton: true } } })

// использование в host
const Catalog = lazy(() => import('catalog/Catalog'))

Опции shared

singleton: trueОдна версия на страницу. При расхождении берётся старшая, младшая сторона получает предупреждение
requiredVersionДопустимый диапазон. По умолчанию — версия из зависимостей приложения
eager: trueЗагрузить сразу, в начальном бандле. Только если модуль нужен синхронно при старте
import: falseНе класть свою копию как fallback, а брать только у хоста
