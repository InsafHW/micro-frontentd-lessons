Справочник · Микрофронтенды

Синхронизация состояния между микрофронтендами

У данных один дом. Остальные получают копии и знают, как наверстать пропущенное.

Три уровня

УровеньКтоПравило
Источник истиныБэкенд домена (BFF команды-владельца)Переживает F5, вкладки, устройства
Владелец на клиентеМФ доменаЕдинственный писатель. Кэш живёт дольше компонента
ЧитателиВсе остальные МФТолько копии через события. Не лезут в чужое хранилище

Проблема → приём

ПроблемаПриёмМеханизм
Компонент выгрузили — данные пропалиХранить состояние вне жизненного цикла компонентаБэкенд; кэш с ключом команда:домен:vN
Опоздавший подписчикСнимок, а не дельта. Рукопожатие в обе стороныЧитатель: x:state-request. Владелец: x:changed при монтировании и на запрос
Действие потерялось, пока владельца нетПодтверждение приёмаcancelable: true + preventDefault(); dispatchEvent() → false = принято
Вкладки разъехалисьВладелец синхронизирует сам себяBroadcastChannel (отправитель своё не получает) или событие storage (не в своей вкладке)

Атрибут или событие?

Атрибут / prop — это состояниеВсегда текущее значение, опоздать невозможно. Подходит, когда владелец — родитель (Shell).
Событие — это моментМожно пропустить. Нужны снимки и рукопожатие. Подходит для соседей.

Код-скелет

// Владелец
let state = await loadFromBackend()                      // или кэш владельца
const announce = () => dispatchEvent(new CustomEvent('cart:changed', { detail: snapshot(state) }))
addEventListener('cart:state-request', announce)
addEventListener('catalog:add-to-cart', (e) => { e.preventDefault(); update(e.detail) })
const bc = new BroadcastChannel('polka-cart')
bc.onmessage = (m) => { state = m.data; announce() }     // из другой вкладки
function update(x) { state = apply(state, x); save(state); bc.postMessage(state); announce() }
announce()                                               // «я загрузился»

// Читатель
addEventListener('cart:changed', (e) => render(e.detail))
dispatchEvent(new CustomEvent('cart:state-request'))

Анти-паттерны

  • Общий store в Shell для доменных данных: Shell начинает владеть чужим доменом.
  • Читатель читает чужой localStorage или ходит в чужой API в обход владельца.
  • Дельты в событиях (+1): один пропуск, и копии расходятся навсегда.
  • Каждый МФ слушает BroadcastChannel чужого домена.
  • BroadcastChannel на file://: в Chrome сообщения не доставляются.
