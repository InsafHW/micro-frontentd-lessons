Каналы связи между микрофронтендами

Общайтесь как можно меньше. Если общаться нужно, выбирайте канал по тому, что передаётся.

КаналНаправлениеЧто передаётПримерЛовушки
Атрибуты / propsShell → МФ ↓Входные данные, которыми владеет контейнер<catalog-list user="Анна">
React/Vue: props при монтировании		Атрибуты — только строки; сложные объекты передавайте свойством или props. Ставить атрибуты чужому МФ может только Shell, но не сосед.
СобытияМФ → кому интересно ↑Факт в прошедшем времени: «добавили», «изменилось»catalog:add-to-cart
cart:changed {count,total}		Нужны bubbles и composed из Shadow DOM. Слушатель, подключившийся позже, событие пропустил (см. урок 2). Контракт неявный, его нужно документировать.
URL⇄ всеНамерение пользователя и навигационное состояние/catalog?genre=sfФормат маршрута становится контрактом между командами, покрывайте его тестами.

Правила

  1. Один владелец у каждого куска данных. Остальные получают копии и никогда не пишут в чужое.
  2. Нет общего store и общих глобальных переменных, даже при одном фреймворке у всех команд.
  3. Префикс команды во всём общем: события, CSS-классы, ключи localStorage, cookies (cart:*, .cart-*).
  4. Нативные API браузера (CustomEvent, атрибуты, URL) вместо самописной шины: так контракт не зависит от фреймворка.
  5. Устойчивость: отправитель события не ждёт ответа. Падение одного МФ не роняет остальные.
  6. Сквозное держит Shell: роутинг, авторизацию и решение, где и когда монтировать МФ.

Быстрый выбор

«Контейнер знает X, МФ нужно X»→ атрибут / prop
«В МФ что-то случилось, другим может быть интересно»→ событие с префиксом
«Пользователь хочет попасть куда-то / это должно пережить F5»→ URL
«Двум МФ постоянно нужны данные друг друга»→ пересмотрите границу

Код

// отправить факт
el.dispatchEvent(new CustomEvent('cart:changed', { detail: { count: 3 }, bubbles: true, composed: true }))
// подписаться (и отписаться при размонтировании!)
window.addEventListener('cart:changed', onChange)
window.removeEventListener('cart:changed', onChange)
