Урок 5 · Микрофронтенды

Изоляция: чтобы чужой CSS и чужая ошибка не роняли твой МФ

Независимые команды работают на одной странице. После урока вы сможете объяснить, как стили одной команды ломают другую и как это предотвратить на трёх уровнях. А ещё — кто и где ловит ошибку, когда МФ падает.

Разминка: урок 4

Почему переход через history.pushState() в обход navigate() ломает страницу, и какое событие Navigation API это чинит? Ответьте, потом откройте.

pushState() не вызывает popstate, поэтому Shell не узнаёт о смене адреса: URL новый, а экран старый. currententrychange срабатывает на push, replace и «Назад». Это страховка, а основа — контракт navigate().

Часть 1. Стили

«CSS как язык по своей природе глобален, наследуется и каскадируется. Традиционно в нём нет модулей, пространств имён и инкапсуляции»[1]. На одной странице с чужими командами это значит: любой ваш селектор может попасть в чужую разметку.

Что я увидел на нашем стенде

Команда Каталога подключила «невинный» button { background: green }. Рантайм федерации добавил на страницу Shell <link> на CSS с сервера Каталога (5171). После этого позеленели кнопка «Войти» в Shell и кнопки на странице Корзины, а Корзина — другая команда и даже другой фреймворк. Хуже того: я ушёл на /cart, Каталог размонтировался, а его CSS остался. Стили не выгружаются вместе с микрофронтендом.

Три уровня защиты

Статья перечисляет способы[1]. Полезно разложить их по тому, кто гарантирует изоляцию:

Сама статья подытоживает: подход «не так уж важен», если разработчики могут писать стили независимо и уверены, что код предсказуемо поведёт себя после сборки в одно приложение[1].

Что проходит через Shadow DOM

Сначала сделайте ставку: какие из трёх «чужих» правил изменят кнопку внутри Shadow DOM? Потом включайте по одному.

Правило по селектору не проходит: это и есть инкапсуляция. Наследуемые свойства (color, font-style) проходят, ведь наследование идёт через границу. CSS-переменные тоже проходят: они наследуются, как и обычные наследуемые свойства[5]. Я проверил все три случая в Chrome на этом стенде.

Отсюда правило для дизайн-системы

Глобальный CSS пишет только Shell: базовый reset и токены — CSS-переменные вроде --catalog и --bad. Команды стилизуют только свою разметку изолированно и берут цвета из токенов. Токены проходят через любой уровень изоляции, поэтому «Полка» выглядит цельной, хотя никто не трогает чужие селекторы. Так устроен Catalog.module.css.

Часть 2. Ошибки

Error boundary из урока 3 — не универсальная сетка. По документации React он ловит ошибки во время рендера дочерних компонентов и не ловит ошибки в обработчиках событий, в асинхронном коде (setTimeout и т. п.), при SSR и в самом boundary[6]. А про Vue-приложение, смонтированное через mount(), React вообще ничего не знает.

Ещё одна находка: после ошибки boundary «залипает» и показывает заглушку, пока его не размонтируют. Если пользователь со страницы книги перешёл на /catalog, Каталог остался «мёртвым». Поэтому в RemoteBoundary.tsx появился resetKey={path}: при смене адреса boundary пробует отрисовать МФ заново.

Правило ошибок

Каждый МФ сам отвечает за свои ошибки: свой errorHandler или boundary и свой логгер. Shell — последняя линия: boundary вокруг каждого remote, .catch на загрузку, сброс при навигации. Так падение одной команды превращается в заглушку на её месте, а не в белый экран.

Лабораторная

Я обновил playground. Если ваши серверы работают, обновите страницу. Если нет: cd playground && npm start.

  1. Устройте утечку. Создайте catalog/src/leak.css с button { background: crimson; color: white }, добавьте import './leak.css' в catalog/src/Catalog.tsx и выполните npm run build -w catalog. Какие кнопки покраснеют? Что будет на /cart? Все кнопки страницы, включая «Войти» в Shell и кнопки Корзины на Vue. На /cart они останутся красными, хотя Каталог размонтирован. Потом удалите файл и импорт и пересоберите Каталог.
  2. Посмотрите на изоляцию. В DevTools наведите на кнопку «В корзину». Какой у неё класс? Что-то вроде _buy_8hz6f_6: это CSS Modules. На странице корзины у кнопки «💥» будет атрибут data-v-…: это Vue scoped.
  3. Две ошибки в Каталоге. На странице книги нажмите «💥 ошибка в onClick», потом «💥 ошибка рендера». Затем «Каталог» в шапке. Что сделает каждая и что вернёт Каталог? Ошибка в onClick: интерфейс цел, ошибка только в консоли, boundary её не видит. Ошибка рендера: заглушка Каталога, шапка и бейдж живы. Переход на /catalog меняет resetKey, и Каталог оживает.
  4. Уберите границу ошибок Vue. На /cart нажмите «💥» и увидите заглушку. Теперь закомментируйте app.config.errorHandler = … в cart/src/mount.ts, выполните npm run build -w cart и повторите. Поймает ли React-boundary Shell? Нет. Страница корзины молча исчезнет: пустое место без сообщения, а React-boundary Shell ничего не заметит. Верните строку и пересоберите Корзину.

Проверьте себя

Последние два вопроса — из уроков 4 и 3.

Каталог подключил button { background: green }. Пользователь ушёл на /cart, Каталог размонтирован. Какие теперь кнопки у Корзины?

Подключённый <link> никто не удаляет: размонтируется DOM-дерево МФ, а не его стили. scoped Корзины защищает от утечки её стилей наружу, но не защищает её разметку от чужих глобальных селекторов.

Shell задаёт --catalog: teal на :root. МФ отрисован внутри Shadow DOM и использует var(--catalog). Что он увидит?

Shadow DOM блокирует селекторы, а не наследование. CSS-переменные наследуются, поэтому токены дизайн-системы проходят внутрь. Это видно на стенде выше. Режим open/closed влияет на доступ из JavaScript, а не на стили.

Какую из этих ошибок поймает React error boundary в Shell?

Boundary ловит ошибки рендера своего React-дерева. Обработчики событий и асинхронный код он по документации не ловит[6]. Vue-приложение для React — просто DOM-узел.

В Корзине обработчик catalog:add-to-cart бросил исключение до preventDefault(). Что произойдёт у Каталога?

Исключения слушателей не доходят до вызывающего кода[8], а остальные слушатели всё равно вызываются (я проверил). Подтверждения не было, значит dispatchEvent вернул true, и Каталог честно говорит «корзина недоступна». Паттерн подтверждения из урока 2 сам выдерживает падение владельца.

урок 4 Каталогу нужно перейти на свою подстраницу /catalog/book/solaris. Как правильно?

Даже свои подмаршруты Каталог меняет через navigate: история одна, адресом владеет Shell. Прямой pushState не вызывает popstate, а location.href перезагрузит страницу и все МФ.

урок 3 Каталог импортирует CSS-файл. Как этот CSS попадает на страницу Shell?

CSS — такой же ресурс remote, как его JS-чанки: он лежит в dist Каталога и грузится с 5171 во время работы. Shell при сборке о нём не знает. Поэтому новый CSS Каталога доезжает без пересборки Shell, в том числе и плохой.

Тренировка для собеседования

60 секунд, вслух:

«Как вы изолируете микрофронтенды друг от друга: стили и ошибки?»

Образец ответа

Стили. CSS глобален, поэтому глобальные правила пишет только Shell: reset и дизайн-токены в CSS-переменных. Команды стилизуют свою разметку изолированно: CSS Modules в React, scoped во Vue, а где нужна гарантия браузера — Shadow DOM. Переменные проходят через все эти уровни, так что общий вид сохраняется. Важная деталь: CSS remote не выгружается при размонтировании, поэтому один глобальный селектор команды может сломать страницу всем, даже когда её МФ уже не на экране. Ошибки. Каждый МФ ловит свои: React — error boundary, Vue — app.config.errorHandler внутри mount. Shell — последняя линия: boundary вокруг каждого remote, .catch на загрузку и сброс boundary при навигации. Error boundary не ловит обработчики событий и асинхронный код, для них глобальный логгер на window.onerror и unhandledrejection. Исключение в слушателе чужого события не доходит до отправителя, а подтверждение через preventDefault позволяет отправителю заметить, что владелец не ответил.
